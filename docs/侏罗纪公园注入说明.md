## 为什么「轮回」不能改？

`侏罗纪公园-轮回.w3x` 是 **KKWE 保护**（凯凯WE 加密），与 `仙之侠道` 同类：

- MPQ 头有效，但**哈希表/块表用非标准密钥加密**（`war3mpq.py` 读不出文件）
- `war3map.j` = **136 字节纯注释存根**，无 `globals`、无 `function main`、无任何代码
- 无 `war3map.wtg`/`war3map.wct`（触发器），无任何 `.j`/`.lua`/`.bin`
- `war3map.w3a` 仅 3 个空技能覆盖（0 mods）

**实测证据**：对副本执行 HKE「注入脚本」，工具报告"注入成功"，但：
- `war3map.j` 仍是 136 字节存根
- 文件数 1781 → 1782，唯一新增的是 `(listfile)`，**没有任何脚本被写入**
- 地图只增大 35 字节

KKWE 把真正的游戏逻辑编译成**自定义字节码**，隐藏在加密的 MPQ 数据块里，`war3map.j` 只是占位符。标准脚本注入没有可挂钩的入口点。

> 建议：换未加密版 / 找开源版 / 用 KKWE 脱壳工具（超出常规改图工具链，且可能违反作者意愿）。

## 关键技术点

### YDWE 地图必须用 inject_script_manual.py

两张图都是 **YDWE 地图**，`war3map.j` 含大量 `//endglobals from XXX` 注释：
- 侏罗纪公园1.5：**30 个** `//endglobals from`
- 逃出神秘岛：含 `constant boolean LIBRARY_BzAPI` 等

HKE 的「注入脚本」按 `endglobals` 子串匹配，**每个出现处都插入一次 f.j** → 31 份副本，脚本爆炸。

**解决**：`tools/war3map-injector/inject_script_manual.py`
自己组装脚本（g.j 插到 `endglobals` 前、f.j 插到真正的 `endglobals` 行后、`call IB_Init()` 插到 main 开头），
再用 HKE「添加/替换文件」写回。验证：恰好 1 个 `IB_Init` 定义 + 1 个 `call IB_Init()`。

### globals 常量顺序

两张图 globals 块都以 `constant boolean LIBRARY_...` 开头。
`inject_script_manual.py` 把我们的非 constant 变量插在 `endglobals` 之前（所有 constant 之后），正确。

### 物品收集

- `collect_items.py <map_dir>`：游戏标准物品 + 地图 `units\itemdata.slk`（权威列表）
- `collect_map_items.py <map_dir>`：地图 `war3map.w3t` 自定义物品（用稳健解析器，绕过 collect_items 的字段漂移 bug）

## 复现步骤

```powershell
# 1. 解压地图
python tools/war3map-injector/extract_all.py "<map.w3x>"

# 2. 收集物品/技能
python tools/war3map-injector/collect_items.py "<map_dir>"
python tools/war3map-injector/collect_map_items.py "<map_dir>"
python tools/war3map-injector/collect_skills.py "<map_dir>"

# 3. 生成 f.j
python tools/war3map-injector/build_fj.py
python tools/war3map-injector/validate_dir.py scripts/item-browser

# 4. 注入（YDWE 图必须用 manual）
Copy-Item "<map.w3x>" "maps/_work.w3x"
python tools/war3map-injector/inject_script_manual.py "maps/_work.w3x" scripts/item-browser

# 5. 部署
python tools/war3map-injector/deploy_mod.py "maps/_work.w3x" "<名称>_item.w3x"
```
