# 主动装备技能与物品特效排障

> 适用范围：Reforged 1.32+ / 3.0，以及使用 JASS、对象数据和 MPQ 注入的
> `.w3x` / `.w3m` 项目。案例来自 Lost Temple 3.0 的霜之哀伤与
> 埃辛诺斯战刃。

## 一、问题现象

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 霜之哀伤丢到地上后没有蓝色符文 | 物体使用的是技能特效，地面光环需要运行时创建；对应 MDX 也可能未导入 | 拾取/丢弃事件管理按物品句柄保存的 effect；导入 `Rune-Blue-Aura_Raised20.mdx` |
| 冰封践踏没有冰环外扩 | 脚本创建 `war3campImported\IceStompRaised.mdx`，但地图中缺少该文件 | 导入 MDX 并写入 `war3map.imp`，用 `War3Log.txt` 验证 |
| 物品自带主动实现后在英雄技能栏消失 | 能力被标成 `aite=1` 时是物品栏专属；或者错误地依赖脚本临时 `UnitAddAbility` | 使用骑士标枪结构：主动放 `iabi` 第一位，设置真实 `icid`，并保持 `aite=0`，由物品引擎把能力授予英雄技能栏 |
| 蛋刀主动技能重复或武器说明重复 | 把“装备技能”文案写在物品悬浮框，同时技能栏已完整显示 | 物品说明只保留物品属性和物品特效；技能栏负责主动技能名称与参数 |
| 快捷键显示两个 `E` | `atp1` 手写 `(E)`，引擎又自动追加快捷键 | `atp1` 只写技能名；快捷键由 `ahky` 和引擎显示 |
| 腐蚀之球只减 5 点护甲 | 对 `AIcb` 写了不适用的 `Idef` | 使用专用字段 `Iarp=8`，并写入 `DataB` 第 2 数据列 |
| 冲锋看似双倍伤害 | 原生 `AUbr` 与脚本同时结算伤害，或路径采样重复命中同一目标 | 改用无原生伤害的 `ANcl`；每次施法维护独立命中 group，每个敌人只结算一次 |
| 叠层时技能栏多出相同 E 图标 | 用于提供攻击力和状态显示的 `A117/A118` 被直接挂到英雄后会露出命令按钮，并抢用同一热键 | 清空二者热键，用 `BlzUnitHideAbility` 只隐藏按钮；不要用会一并禁用被动的玩家可用性开关 |
| 蛋刀装备后多出一个空按钮 | 内部被动魔法书 `A116` 标记为 `aite=0`，被物品引擎当成英雄能力显示 | 将内部魔法书设为 `aite=1`，并在同步时用 `BlzUnitHideAbility(u, 'A116', true)` 隐藏按钮；书内 `A110/A111` 被动继续生效 |
| 叠层后攻击力和状态都不生效 | `SetPlayerAbilityAvailable(..., false)` 隐藏了按钮，也禁用了 A117/A118 的被动效果 | 改用 `BlzUnitHideAbility(unit, id, true)` 做逐单位 UI 隐藏 |
| 点击技能后鼠标指针消失 | `Ncl3` 的 Targeting Image 位会绘制 Target Art；Target Art 为空时会把正常选择目标光标弄没 | 按澄海 A01M/LS30 实测结果使用 `Ncl3=1`，关闭 Targeting Image |
| 点远处目标时英雄先走过去 | `aran` 只有 900，超出施法距离时引擎会先让英雄进入范围 | 把目标选择距离扩大到 `100000`；脚本按施法瞬间敏捷计算实际冲锋距离 |
| 点击目标后怪物会抢占技能 | Channel 的 Disable Other Abilities 被设成 0，智能命令仍会执行攻击 | 照澄海 A01M 使用 `Ncl5=1`，在施法阶段禁止其它技能/攻击抢占 |
| 点任何远处目标都会先走过去 | 等 `SPELL_EFFECT` 时引擎可能已把目标点击转换成接近目标的订单 | 监听 `EVENT_PLAYER_UNIT_ISSUED_POINT_ORDER`，匹配 `OrderId("channel")` 后在订单当拍取消并用 `GetOrderPointX/Y` 接管方向 |
| 攻击加成加到白字而不是绿字 | `AIaa/Iaa1` 修改基础攻击力 | 使用霜之哀伤同款 `AIat/Iatt` 攻击加成，显示为绿字且不污染基础白字 |
| 丢掉再捡起装备后技能冷却刷新 | 移除后重加技能会创建新的冷却实例 | 移除前读取并保存剩余冷却，重装后按经过时间恢复；不要依赖技能实例自动记住冷却 |
| 丢掉装备后命令栏技能仍然可见或还能释放 | 当前 Reforged 运行时中，`BlzUnitHideAbility` 和 `BlzUnitDisableAbility(..., true, true)` 都未可靠撤下已添加的 A113 | 卸装时直接 `UnitRemoveAbility`，并保存剩余冷却；事件英雄用 `GetTriggerUnit()` 获取 |
| 冲锋动作像普通走路 | 位移期间使用 `walk` 动画 | 使用 `attack slam`（兽王挥斧类动作），结束时 `ResetUnitAnimation` |
| 冲锋后技能没有冷却 | 结束时清理订单会中止 Channel 的冷却提交 | 施法开始时启动冷却；执行 `stop` 后再检查剩余冷却，若被清零则用 `BlzStartUnitAbilityCooldown` 补上 |
| 冲锋结束又跑回施法点并重复施放 | 暂停期间保留了原始点目标施法指令，解除暂停后引擎恢复旧订单 | 施法开始与结束时清除订单；结束时先恢复暂停/寻路，再 `IssueImmediateOrder(caster, "stop")` |
| 一次按键出现重叠冲锋 | `SPELL_EFFECT` 可能重复到达，运行时无条件为每次事件新建 timer | 以施法者句柄保存当前 timer；事件到达时已有活动 timer 就忽略后续事件 |

## 二、物品主动和英雄技能栏

主动技能用于物品施放时，例如霜之哀伤的冰封践踏：

```text
I105.iabi = A105,A106,A108,A109
I105.icid = A105
```

`A105` 必须位于 `iabi` 第一位，物品图标才会显示冷却反馈。

装备物品自身携带主动技能时，例如《被遗忘者国度》的骑士标枪：

```text
etkj.iabi = Atkj
etkj.icid = Afoa
etkj.icla = Equipment
etkj.iequ = Trinket
```

骑士标枪的关键不是脚本，而是物品数据本身：

- `Atkj` 是实际主动能力，位于物品技能列表第一位；
- `Afoa` 只是独立冷却组 ID，不要求与主动能力相同；
- 物品类别必须是 `Equipment`，装备槽类型为 `Trinket`；只放在普通背包时，
  物品引擎不会把它视为已装备，因此不会授予 `iabi`；
- `UnitHasItemOfTypeBJ` 只检查普通背包。装备槽内物品应通过
  `BlzUnitItemInEquipmentSlot(unit, ConvertLoadoutSlot(8))`、
  `UnitHasItemOfTypeEquippedBJ` 或同类 loadout API 判断；
- 原版 `Atkj` 的“物品能力” `aite` 为 `0`，因此装备后直接出现在
  英雄技能栏；`usable=0` 只表示不能当消耗品右键使用；
- 跨章节时引擎重新读取物品的 `abillist/cooldownid`，不需要脚本再次
  `UnitAddAbility`，所以物品存在时技能和冷却归属都能重建。

`aite` 决定能力的 UI 归属：

- `aite=0` + `iabi/icid`：物品授予英雄技能栏能力，骑士标枪使用此模式；
- `aite=1`：物品栏专属能力，适合只从物品图标触发的效果；
- 两者都不要再用脚本给同一 ID 重复 `UnitAddAbility`。

当目标章节不支持可靠物品授予时，蛋刀的旧回退方案使用
“装备时添加、卸下时移除、冷却状态另存”：

```text
有 I106：UnitAddAbility(A113)
         若保存过冷却，BlzStartUnitAbilityCooldown(剩余时间)
无 I106：保存 BlzGetUnitAbilityCooldownRemaining(A113)
         UnitRemoveAbility(A113)
I106.iabi = A110,A111,Aclq
I106.icid =
```

本项目当前 Reforged 运行时先后实测了 `BlzUnitHideAbility` 以及
`BlzUnitDisableAbility(..., true, true)`，卸下 I106 后 A113 仍会显示。
因此需要可靠消失时必须移除技能。重加造成的冷却刷新用独立状态解决：
保存绝对到期时间，重装时计算真正剩余的冷却。

蛋刀的敏捷/动态攻速不放进外层魔法书，而是直接把 `A110,A111` 留在
物品 `iabi` 中。`A116` 只是兼容旧构建的隐藏书本对象，不再由成品物品引用。

丢弃和拾取事件应使用 `GetTriggerUnit()`，并且只依据当前事件的
`GetManipulatedItem()` ID 做直接授予/移除。不要再追加 `0.05` 秒后的
“等库存更新再同步”：实测这个二次同步不可靠，也无法解决章节切换。
章节切换应由物品 `iabi/icid` 持久所有权负责；旧数据回退方案则在读档事件
和明确的载入阶段同步点恢复，而不是依赖事件延迟。

选择技能所有权时先确定需求：

- 需要英雄技能栏按钮且跨章节保留：优先 `aite=0` + 物品 `iabi/icid`。
- 只需物品栏触发：使用 `aite=1` + 物品 `iabi/icid`。
- 数据版本不支持物品可靠授予时：装备添加、卸装移除；冷却跨丢捡另存恢复。
- 不要同时使用两种方式；同一 ID 同时由物品和英雄携带可能出现重复按钮，
  并让冷却归属不明确。

Reforged 中隐藏被动按钮可用 `BlzUnitHideAbility`；不要用
`SetPlayerAbilityAvailable(..., false)` 代替，它可能同时禁用被动效果。
这条只适用于被动按钮。命令栏活动技能卸装时应直接移除 A113；本运行时
已经证明隐藏或禁用不能可靠撤下按钮。
仅面向 1.27 的图应改用项目已验证的隐藏魔法书方案。

## 三、主动技能数据不要依赖原生冲锋状态机

蛋刀的雷霆冲锋以 `ANcl` 为底，只保留一级：

```text
A113.old = ANcl
alev = 1
aran = 100000
acdn = 16
amcs = 70
```

`Ncl2=2` 表示点目标，`Ncl3=1` 只保留 Visible。按澄海 A01M 使用
`Ncl1=1.16`、`Ncl4=1.16`、`Ncl5=1`；最后一项防止附近怪物和其它技能抢占。
`A113` 不设置 `abuf`，不能继承 `BUbr`。

即使把 `aran` 放大，`SPELL_EFFECT` 仍可能在引擎完成接近订单后才到达。
若点击点只代表方向，应监听
`EVENT_PLAYER_UNIT_ISSUED_POINT_ORDER`，在
`GetIssuedOrderId() == OrderId("channel")` 时读取
`GetOrderPointX/Y()`、取消原订单，并从当前坐标启动冲锋。`SPELL_EFFECT`
只保留为防重复回退路径。

脚本以 `0.05` 秒周期直接设置坐标，每步 50；总距离在施法瞬间按
`100 + 敏捷×10`、最高 2000 计算并存入该次施法状态，不读取 `IsTerrainPathable`。
玩家可见说明保持为：`冲锋距离：100 + 敏捷×10，最高 2000。`
每次施法维护独立命中 group，保证路径上每个敌人只受伤一次。结束时无论
正常完成、死亡还是中断，都必须恢复 `PauseUnit(..., false)` 和
`SetUnitPathing(..., true)`。

点命令条件和脚本入口都应再次检查英雄仍持有 I106。卸装移除解决按钮
表现，持有物检查则防止旧事件或残留订单绕过装备所有权。

叠攻由独立对象实现：`A117` 使用 `AIat/Iatt` 提供 1–20 级、每级 +15
绿字攻击力；`A118` 只负责显示自定义 `B64B`。`AIaa/Iaa1` 会把数值加到
白字/基础攻击，属于错误层级。两者都不能暴露 E 热键或可点击按钮；
Reforged 运行时使用 `BlzUnitHideAbility` 隐藏按钮，被动加成和状态效果仍然保留。

冲锋移动使用 `attack slam`，结束时调用 `ResetUnitAnimation`。普通
`walk` 会让脚本位移看起来像步行。

## 四、腐蚀之球字段

`AIcb` 的护甲损失不能使用 `Idef`。标准 `AIcb` 对应的专用对象字段是
`Iarp`，语义是“护甲损失量”：

```text
Iarp = 10
level = 1
column = 2
```

不要写成 `Idef=-10`。`Idef` 面向其他护甲能力，写到 `AIcb` 上会被忽略，
实际仍继承原版 -5。

蛋刀的物品栏若同时包含吸血法球 `AIva`，会与腐蚀法球发生法球互斥。需要
避免同时挂两个法球类能力；属性被动可放入隐藏魔法书，腐蚀法球单独留在
物品主能力位。

## 五、霜之哀伤主动冰环

冰封践踏的对象数据应保持：

```text
A105.old = ANcl
A105.aord = froststomp
A105.Ncl6 = froststomp
A105.Ncl2 = 0
A105.Ncl3 = 1
A105.aani = stand
```

当前实现使用瞬发 `ANcl`，只监听 `SPELL_CAST`/`SPELL_EFFECT`，由脚本
结算伤害和冻结；耗蓝与冷却由引擎负责。不要再额外拦截 `froststomp`：
双入口会让 `stop` 清掉冷却，同时防重锁挡住下一次脚本结算。因为蛋刀
`A113` 也使用 `ANcl`，
同一英雄不能同时携带 `I103`、`I105`、`I106`。`additem` 在
`UnitAddItem` 前检查已有神器，冲突时直接创建在地上；其他拾取来源在
背包状态稳定后把新物品掉在英雄前方。

脚本等待 `0.05` 秒后造成 `100 + 4×力量`，普通单位冻结 5 秒、
英雄 3 秒，并使用 `Bfrz` 对应的 `FreezingBreathTargetArt.mdl`。
魔免单位只冻结、不受伤。

仅写 `acat` 路径不够，还必须把文件本身导入地图：

```text
heroes/frostmourne/assets/IceStompRaised.mdx
  -> war3campImported\IceStompRaised.mdx
```

同时更新 `war3map.imp`。如果日志出现：

```text
model creation failed - war3campImported\IceStompRaised.mdx
```

应直接把它判定为资源缺失，而不是继续检查技能冷却或触发器。

冰封践踏本身使用 `AOws` 作为主动物品技能，因此物品说明应保留主动技能参数；
不要把物品说明压缩成“详情见技能栏”，否则物品绑定主动技能无法明确说明。

## 六、霜之哀伤地面符文

地面符文不是物品 `ifil`，而是根据物品是否在地上动态创建：

```text
war3campImported\Rune-Blue-Aura_Raised20.mdx
```

可靠流程：

1. 导入符文 MDX，并写入 `war3map.imp`。
2. 丢弃事件发生后等待约 `0.05` 秒，确认物品已进入地面状态。
3. 以物品句柄 ID 为 key，记录 effect、坐标和物品句柄。
4. 拾取事件销毁 effect、清空 hashtable，并从记录数组中移除。
5. 进场时只枚举一次地面物品，恢复已有物品的符文。
6. 不要每帧重复创建 effect；重复创建会表现为叠光或掉帧。

如果项目要求物品被脚本移动时符文跟随，可使用低频更新；普通玩家丢弃流程用
拾取/丢弃事件即可，不需要每 0.25 秒扫描全世界。

## 七、推荐验收顺序

1. 对象回读：`iabi`、`icid`、`acat`、`Iarp`、`A113/old`、A117 的 20 个等级。
2. MPQ 回读：所有 MDX 均存在且以 `MDLX` 开头。
3. 重新启动 War3，不要只重开当前地图。
4. 检查最新 `War3Log.txt`，确认没有对应 `model creation failed`。
5. 蛋刀：首次装备后英雄技能栏显示“雷霆冲锋”，快捷键 E；丢弃时按钮立即消失且不能释放。
6. 蛋刀：目标护甲实际减少 8，重复命中不叠加。
7. 蛋刀：路径上每个敌人只扣一次 3×敏捷，不同敌人各增加一层攻击状态。
8. 蛋刀：7 秒无新增层后 A117/A118/B64B 同时消失；攻击加成显示为绿字。
9. 蛋刀：冷却中丢弃再捡起，剩余冷却不刷新，重装后按剩余时间继续。
10. 蛋刀：不同敏捷下冲锋距离按 `100 + 敏捷×10`、最高 2000 变化，动作使用挥击动画。
11. 霜之哀伤：物品主动施放能看到冰环，落地后看到符文，拾取后符文消失。
