# HkeW3mModifier 2.05 行为实测记录

> 实测环境：`H:\Games\War3\Tools\151个常用脚本\脚本\HKE1.25(5.17美化版）\HKE1.25(5.17美化版）\HkeW3mModifier2.0.exe`
> 实测对象：`maps/LostTemple/LostTemple.original.w3m`（官方加密 RoC 图）、`maps/伏魔战记.w3x.original`（YDWE 图）

这些结论是写 `tools/war3map-injector/hke_session.py` 的依据。踩过的坑都记在这里，
避免重新用 GUI 试错的方式再摸一遍。

## 一、速度

| 步骤 | 实测耗时（0.3MB 图） |
| --- | --- |
| 拖放打开地图 | 0.3~0.5s |
| 「分析文件」 | 约 1.3s（旧脚本固定 sleep 8s） |
| 「解压文件」 | 0.3~1s（旧脚本固定 sleep 3~5s） |
| 「添加/替换文件」 | 0.2~1.5s（旧脚本固定 sleep 2s + 弹窗各 1s） |
| 「重压缩」 | 2~3s，且**没有任何可观察效果**（见下） |

旧脚本的固定 sleep 合计约 20~30s/次，是"一次部署要等很久"的主要来源。

## 二、「重压缩」可以不用

实测：点「添加/替换文件」之后**地图文件当场就被改写了**（sha256 立刻变化）。
再点「重压缩」，连续 30s 观察文件大小与 mtime **完全没有变化**。

结论：替换完直接关闭即可，改动已经落盘。工具自己的说明也提到
「如果重压缩卡死 生成超大文件可以试试修复文件头」，说明该功能本身容易卡死——
旧脚本点完只等 6~8s 就 `taskkill`，正可能把卡住的重压缩强杀，写出坏图。

副作用：HKE 采用"追加"方式写入，地图体积会随替换增大（不会自动回收）。
介意体积时可以手动点一次「重压缩」或「修复MPQ头」。

## 三、控件与按钮的实际文案

主窗口类名 `THkeForm`（比按标题找窗口可靠，标题会变成 `... 当前文件:xxx.w3x`）。

| 分组 | 控件 |
| --- | --- |
| 功能区 | `打开地图(&O)`、`解压文件(&U)`、`重压缩(&C)`、`删除文件(&D)`、`添加/替换文件(&A)`、`关闭文件(&X)`、`文件分析(&M)`、`修复MPQ头[重压缩卡死可试试](&R)`、`删除地图效验文件(&X)` |
| 文件选择 | `Jass脚本` / `自定义文件` 单选钮 + 一个路径框 |
| 文件添加选项 | `采用上方文件选择中的完整文件名` / `采用自定义路径+文件名 路径如下:` + 一个路径框 |
| 文件列表 | `分析文件(&F)`、`全部解压[列表中的文件](&N)`、`保存列表(&S)`、`清空列表(&L)`、`TListBox` |

## 四、添加文件的命名规则（最大的坑）

HKE 的「添加/替换文件」默认按**「Jass脚本」**处理，会把目标名强行设为 `war3map.j`。

症状：连续替换 `war3map.w3a`、`war3map.w3t`、`war3map.w3h` 时，三个文件
**全部被写进 `war3map.j`**，并弹出
「发现文件名不一致,您确定要把 X 添加到 war3map.j 么？」。

正确做法：每次添加前先点 **「文件选择」里的「自定义文件」**。
之后目标名取所选文件的名字，连续替换互不干扰。（旧工具 `inject_file.py` 留下的
`war3map.w3a\war3map.w3a` 这种怪名字，就是这个机制用错导致的。）

另外：

* 目标名**只由文件名决定**，所以源文件必须先复制成"文件名 == 内部名"再选，
  例如复制成 `_rep\war3map.w3a`。
* 想改内部名时可以勾「采用自定义路径+文件名」并在下面的框里填路径，
  但**不要留空**——实测留空会让后续「解压文件」失效（解不出任何文件）。
* 「采用上方文件选择中的完整文件名」会把整条路径当成内部名，一般不要用。

### 4.1 添加"地图里原本没有的新文件"时只保留文件名

实测（2026-10-10，注入自制的 buff 图标）：

* 请求的内部名写 `ReplaceableTextures\CommandButtons\BTNWingHeal.blp`，
  源文件必须复制成同名——但 Windows 文件名里不能有 `\`，`hke_session.replace()`
  又是用**文件名**当内部名的。
* 结果 HKE 把文件加成了**根目录的裸名**，并且**压成小写**：列表里出现 `btnwingheal.blp`。
  后续校验（拿请求的名字去列表里比对）失败，整次注入被判失败、跳过部署
  （但文件其实已经写进地图了）。
* 所以：**给地图添加新文件时，内部名就用全小写裸名**，字段里也写这个裸名。
  根目录裸名是可以被引用的——本工程的翅膀模型 `WingOfTheLucifer.MDX` 就是根目录裸名，
  技能 `atat` 字段里写的也是裸名，游戏能正常加载。

## 五、解压输出位置

「解压文件」把文件写到**地图文件所在目录**，文件名取内部名的最后一段：

```
maps/LostTemple/LostTemple.w3m  --解压 war3map.j-->  maps/LostTemple/war3map.j
```

## 六、列表选择必须补发通知

`LB_SETCURSEL` 只改光标，**不产生 `LBN_SELCHANGE`**，Delphi 端记录的"当前文件"
不会更新，于是「解压文件」会解出上一次操作的文件（实测：选了 `war3map.w3a`，
解出来的却是 `war3map.j`）。

解决：`LB_SETCURSEL` 之后补一条
`WM_COMMAND(LBN_SELCHANGE)` 通知父窗口。

## 七、稳定性

工具说明里就写着「如果不稳定出现错误重启本软件即可」。

实测：一次会话里连续做多次"替换"之后，「解压文件」会失灵（点击后不再产出文件），
但「分析文件」和「添加/替换文件」仍然正常。

因此 `hke_session.py` 的策略是：

* 需要读取地图内文件时，**在会话早期一次读完**；
* 注入本身不依赖解压，放在后面做；
* 校验可以在关闭后另开一次会话（`verify_inject.py`）。

## 八、进程管理

旧脚本用 `taskkill /IM HkeW3mModifier2.0.exe /F` 收尾，会顺手杀掉用户自己开着的 HKE。
应改为记录自己启动的 PID 并只结束它；确实有残留进程时用 `--kill-stale` 显式清理。
