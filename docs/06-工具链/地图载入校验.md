# 地图"找不到 / 损毁"排查手册

> 2026-10-11 记录。起因：战役《血色使命 I》翅膀版进游戏报"提示找不到地图或者损毁"。

## 结论一：战役章节必须"原样存储"（这才是报错的主因）

战役 `.w3n` 里的章节 `.w3x` 是**归档里的归档**：游戏加载某章时是用
`SFileOpenFileAsArchive` 把 `.w3n` 里那个章节**当内嵌 MPQ 打开**的。
**Storm 只支持把"未压缩存储"的子文件当归档打开**——压缩过的块直接打开失败，
游戏就报"找不到地图或者损毁"。普通地图不受影响（直接当归档打开，压不压缩都行），
所以症状是"只有战役进不去"。

证据（用游戏自带 Storm.dll 复现，`sfmpq_subarchive.ps1`）：

```
原版战役   chapter1.w3x   open-as-archive: OK   (inner war3map.w3i = 609 bytes)
改坏的包   chapter1.w3x   open-as-archive: FAIL      ← 用户看到的报错
修好后     chapter1.w3x   open-as-archive: OK
```

原版战役里 19 个章节全部是未压缩存储（`flags=0x80000000`, `csize==fsize`）。
我们之前的打包器一律按压缩写 → 19 章全打不开。

**修复**：`inject_native.py` 新增 `--store <内部名>`（原样存储）；
`port_wings_campaign.py pack` 自动把**所有章节 .w3x/.w3m**（以及原战役里本来就是
未压缩的那些文件）用 `--store` 写进去。修好后新包的存储画像与原版完全一致
（347 文件 / 19 个未压缩 / 19 章全部未压缩），Storm 逐个读 347 个文件 0 失败。

## 结论二：脚本入口调用不能插在 main 的 local 之前

`inject_script_manual.build_script()` 把模块入口调用
（`call TimerStart(CreateTimer(), 0.0, false, function WG_Init)`）插在了
`function main takes nothing returns nothing` 的**下一行**。JASS 规定
`local` 声明必须位于函数体所有语句之前，而战役序章（过场动画那章）的 main 是

```jass
function main takes nothing returns nothing
    call TimerStart(CreateTimer(), 0.0, false, function WG_Init)   ← 插在这里
    local weathereffect we                                         ← 语法错误
```

→ 该章脚本编译失败（同样会让游戏报"找不到地图或者损毁"）。

**修复**：入口调用改为插在"最后一个前导 local 之后"；
并在 `jass_gate.py` 加了构建期门禁（注入前后用 pjass 对比，出现新的错误类型就直接报错、拒绝写出）。

顺带用 `fix_main_locals.py` 修好了同样中招的 `Maps\mod\侏罗纪-逃出神秘岛_item.w3x`
（它那处是 `call IB_Init()` 后面跟着 `local weathereffect we`）。

## 三个本地判据（不用进游戏）

> 平台图（KK/KKWE 壳图）另有一道**专治单机**的锁：哈希表里 2734 条 `wPlatform = 0xFF00`，
> 原版 Storm 直接不认这些条目 → 引擎读不到 `w3i/w3e` → 选图界面玩家列表空白。
> 见 [`KKWE平台图单机化.md`](KKWE平台图单机化.md)。

| 判据 | 工具 | 能证明什么 |
|------|------|-----------|
| 容器 / 文件能否被游戏读 | `sfmpq_probe.ps1`（SFmpq.dll → **游戏自带 Storm.dll**） | 逐文件开门、读尺寸 + md5；游戏读得出来 = 容器没问题 |
| 章节能否被当成内嵌归档打开 | `sfmpq_subarchive.ps1` | **战役是否可玩的关键判据**；改完 `.w3n` 必跑一遍 |
| 脚本能否编译 | `jass_gate.py`（pjass + JassCraft 的完整 common.j/blizzard.j） | 注入前后错误类型对比；`rc=0` = 干净 |
| JASS 语法硬规则 | `check_locals.py` | 任何函数里"语句出现在 local 之前"都会被点名（对用 hashtable 的 1.24+ 图也有效，pjass 那套 common.j 太老、判不了） |
| 对象数据有没有被改坏 | `_objcmp.py` | 比对改写前后的"原始条目"是否一致 |

## 两个曾经误判的点（别重复踩）

1. **"原生写入器写的地图游戏不认"——错。**
   实测用 SFmpq → 游戏自带 Storm.dll 打开 `LostTemple_wings.w3x` 和战役 `.w3n`，
   所有内部文件都能完整读出，且与本地文件逐字节一致；把内容用修好的读取器从零重做一遍，
   产物 md5 完全相同。容器（`mpq_patch.py` / `inject_native.py`）可以放心用，快得多。
2. **`war3mpq.py` 的读取器有静默损坏 bug（已修）。**
   分块读取时无条件尝试解压，把"原样存储"的扇区当 raw deflate 解出垃圾字节（随机数据也能吐出几个字节），
   表现为大文件（章节地图、blp、mp3）读出来"尺寸对但内容不对"，甚至 hash 表读空报
   `actual buffer size is 0`。
   修法：**只有 `stored < 该扇区原始长度` 才解压**。
   ⚠ 结论：本地校验以 **Storm 读回** 为准，别只信自己的读取器。

## 战役翅膀版重新构建（命令）

```powershell
$bak = (Get-ChildItem "H:\Games\War3\Campaigns" -Filter "*.w3n.bak").FullName
python tools\war3map-injector\port_wings_campaign.py extract "$bak" --work maps\port\blood1
python tools\war3map-injector\port_wings_campaign.py config  --work maps\port\blood1 --force
python tools\war3map-injector\port_wings_campaign.py objects --work maps\port\blood1
python tools\war3map-injector\port_wings_campaign.py name    --work maps\port\blood1
python tools\war3map-injector\port_wings_campaign.py chapters --work maps\port\blood1
python tools\war3map-injector\port_wings_campaign.py pack "$bak" --work maps\port\blood1 --out "...\血色使命 I 十周年纪念版(翅膀版).w3n"
```

`chapters` 会自动跳过已注入（脚本里已有 `WG_Init`）的章节；要整章重做就先重跑 `extract`。
