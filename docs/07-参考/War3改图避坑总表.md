# War3 改图避坑总表

> 适用范围：经典版 War3 1.24–1.28（重点为 1.27），以及本项目中的 `.w3x`、`.w3m`、`.w3n` 移植、对象数据、JASS、MPQ 注入和资源导入。
>
> 本文记录已经实际遇到过并定位过的问题。排错时先看“症状速查”，再查对应章节。

## 一、症状速查

| 症状 | 常见根因 | 正确处理 |
|---|---|---|
| 物品第 5 个被动没效果，但对象数据明明存在 | 物品 `iabi` 最多只认 4 个技能 | 合并/删除无实际作用的技能，确保最终不超过 4 个 |
| 主动技能没有冷却转圈 | 主动技能不在 `iabi` 第一位，或 `icid` 不对 | 主动技能排第一，`icid` 使用真实主动技能 ID |
| 物品模型不可见、看不到、点不到 | `ifil` 指向的 MDX 不存在，或 MDX 依赖的 BLP 未导入 | 同时导入 MDX 和它的全部贴图依赖，并核对完整路径 |
| 只有地面光环，没有剑模型 | 只导入了光环，缺少物品 `ifil` 模型或其贴图 | 解析 MDX 字符串中的 `.blp` 依赖，一并导入 |
| 最大生命浮字出现但数值没变 | 改的是当前生命，或能力没有重新结算 | 区分当前生命/最大生命；不要只改同一被动能力等级 |
| 最大生命上限偶尔不扣 | 对同一 `AIl2` 调用 `SetUnitAbilityLevel` 可能不刷新 | 使用独立能力按二进制组合累计扣除 |
| 主动技能打不到空中单位 | 基技能 `AOws` 原生只认 ground/organic；仅改目标表不一定足够 | `atar` 加 `air`，并对飞行单位用脚本补冻结 |
| 飞行单位被冻结后偶尔永久不动 | 单一全局冻结计时器遇到死亡/失效句柄，回调可能中断后续解冻 | 每个单位使用独立计时器；失效句柄只清理状态，不再调用 `PauseUnit` |
| 图标绿色方块 | 图标路径不存在，或缺 `DIS...` 禁用图标 | 检查 BLP 存在性；菜单暂停时同时检查禁用图标 |
| 加载地图直接返回选图界面 | `war3map.j` 语法错误、编码错误、对象 ID 无效 | pjass + 1.27 地图检查 + 对象字段断言 |
| 新增脚本后函数重复定义 | 在已经注入过脚本的成品图上再次追加同一模块 | 永远从注入前基线或干净章节重新构建 |
| 地图有一大片特效反复生成/响声音 | 定时器每次创建特效但未按句柄复用，或拾取后未销毁 | 以物品/单位句柄为 key 管理 effect，及时销毁 |
| 物品丢下后不可拾取 | 模型缺失、模型无有效可点击区域，或 `idro=0` | 先补模型/贴图，再检查物品是否被设为不可丢弃 |
| 玩家输入中文物品名失败 | 1.27 聊天输入与脚本编码不一致 | 同时维护 UTF-8 显示名、GBK 匹配名和英文命令别名 |
| 战役对象数据无法用普通解析器读取 | 战役级 original 段可能使用带基对象前缀的字段 ID | 使用本项目解析/合并工具，保留 orig/custom 两段 |
| 任务文字很久后才出现 | 客户端字幕开关或过场状态，而非缺少触发器 | 先检查客户端字幕设置和过场触发器 |
| 全屏卡死、声音仍在、Ctrl+Alt+Del 无响应 | 显卡 TDR/驱动/全屏模式问题，不一定是地图脚本 | 检查事件日志和 TdrDelay，避免把系统问题误判为地图崩溃 |

## 二、基线与版本纪律

1. 修改前先确认实际目标文件。`mod` 目录可能同时存在多张官方图、旧测试图和同名副本。
2. 优先从已验证稳定版或“注入前基线”构建，不在多轮成品图上盲目叠加。
3. 每次重要修改保留一个已知可运行版本、提交或标签，并记录 SHA-256。
4. 检查地图真实版本。基于 1.27 的项目不能用只适用于 Reforged 的原生 API。
5. 只修改用户指定的地图和系统。用户没有说明时，不默认添加坐骑、翅膀或英雄。
6. 修改战役时统一使用 `alas` 前缀；不要给文件名添加额外版本后缀。
7. 部署后比较工作区与游戏目录的 SHA-256，避免“代码改了但游戏加载的是旧图”。

## 三、物品对象数据

### 3.1 物品技能最多 4 条

物品 `iabi` 只有 4 个有效位置。第 5 条不会报错，而是静默失效。

实际案例：

```text
A105 冰封践踏
A106 攻击速度
A107 霜冻攻击（额外伤害已为 0）
A108 攻击力
A109 魔法恢复
```

`A109` 是第 5 条，因此魔法恢复没有生效。正确装配为：

```text
A105,A106,A108,A109
```

原则：

- 主动技能放第一位，物品图标才会显示冷却。
- `icid` 使用真实技能 ID，避免不同物品共享冷却。
- 没有实际作用的被动技能不要占位置。
- 改变物品技能列表后，物品浏览器对物品能力的保护列表也要同步。

### 3.2 物品字段名称

物品对象数据中，名称和提示实际使用：

```text
unam
utip
utub
ides
```

不是部分旧文档里的 `inam/itip/iutb`。

对象数据字符串通常按 UTF-8 存储；`war3map.j` 的中文匹配字符串存在 GBK 用法，不能混为一谈。

### 3.3 可丢弃、可出售、死亡掉落

| 字段 | 含义 |
|---|---|
| `idro` | Can be dropped，是否可主动丢弃 |
| `idrp` | Dropped when carrier dies，死亡时是否掉落 |
| `ipaw` | Pawnable/sellable，是否可卖给商店 |
| `isel` | Sellable，出售相关设置 |

花色战役主角专属武器 `I627「衔月」` 的做法是：

```text
idro = 0
ipaw = 0
```

因此它能做到不可丢弃、不可出售，且不需要额外触发器。

测试物品地面模型时必须把 `idro` 恢复为 `1`。否则模型可能已经正确，但玩家无法通过正常操作把物品放下来。

### 3.4 最大生命与当前生命

`GetUnitState(u, UNIT_STATE_MAX_LIFE)` 是最大生命上限，不是当前生命。

降低最大生命时：

```text
800 / 1000 -> 800 / 980
```

当前生命低于新上限时不会变化。只有当前生命高于新上限时才会被夹到新上限：

```text
995 / 1000 -> 980 / 980
```

如果确认最大生命数字本身没有下降，就不能用这条显示逻辑解释，必须检查能力是否真正重新结算。

### 3.5 不要依赖同一 `AIl2` 的等级刷新

对同一个 `AIl2` 最大生命能力反复 `SetUnitAbilityLevel`，存在效果未重新结算、浮字出现但上限不变的问题。

可靠方案：

- 为 `-N`、`-2N`、`-4N`、`-8N` 等权重各创建一个独立能力。
- 记录累计触发次数。
- 每次按累计值的二进制位添加/移除对应能力。
- 写入后比较前后 `UNIT_STATE_MAX_LIFE`，只有实际上限下降才更新累计值和显示浮字。

本项目霜之哀伤使用 `A130`–`A141`，每次 +1 次触发，扣除 50 点最大生命。

### 3.6 物品说明不要靠堆行数

标准物品提示框高度有限。出现过以下现象：

- 标题与物品名称重复。
- 底部“灵魂代价”只显示到一半。

处理方式：

- `utub` 不重复橙色物品标题。
- 将“攻击速度 +50%、攻击力 +30、魔法恢复”压缩到同一行。
- 将主动技能参数压成 2–3 行。
- 重要代价放在末尾前，避免被截断。
- 长玩法说明放在 `ides` 或外部知识库，不全部塞进悬浮框。

## 四、技能与触发器

### 4.1 空中目标

`AOws`（War Stomp）原生目标为 `ground,organic`。只把它改成“看起来支持空中”不一定是完整方案。

可靠处理：

1. 将 `atar` 加入 `air`。
2. 脚本伤害枚举不要排除飞行单位。
3. 若基技能冻结对空不稳定，对 `UNIT_TYPE_FLYING` 单独执行暂停并在计时器到期后恢复。
4. 英雄和非英雄分别使用对应冻结时长。
5. 死亡或单位句柄失效时也要解除暂停并清理记录。

不要用一个全局定时器遍历所有被冻结单位。只要其中一个单位在冻结期间被移除、替换或变成无效句柄，后续 `PauseUnit` 调用就可能中断回调，导致该批单位永久冻结。可靠做法是“每个单位一个 timer”，重复命中时只重启这个单位自己的 timer。

### 4.2 物品主动与物品被动

- 主动技能必须是 `iabi` 第一位。
- 物品被动直接列在 `iabi`，不要默认认为放进魔法书一定生效。
- 魔法书里的物品版被动可能不生效；单位版光环与物品版光环行为也不同。
- 技能 ID 变更时，同时更新 `iabi`、`icid`、物品浏览器保护列表和脚本里的技能常量。

### 4.3 指向技能与位移特效

- 指向技能必须有正确鼠标指针。
- 闪电、投射物等视觉效果应从施法者位置发出。
- 事件回调中使用错误坐标，会出现“从附近空地打到目标附近”的现象。
- 对魔免、建筑、空中、英雄要分别明确伤害、控制、特效是否生效。

### 4.4 不要随意使用 Channel

除非原始参考实现本身使用了 Channel，否则不要用 Channel 拼技能。已遇到过：

- 显示为基础技能“通魔”。
- Follow Through/Disable Other Abilities 导致单位卡住。
- 点击后没有正常目标指针或释放手感。

## 五、JASS 与脚本注入

1. JASS 的所有 `local` 声明必须位于函数体语句之前。
2. 函数调用和条件不要跨行拆分；JASS 不支持现代语言式多行表达式。
3. 所有创建出来的 group、timer、trigger、effect、agent 都要有明确生命周期。
4. 局部 unit、item、group、effect 等 agent 用完置 `null`。
5. 随机数必须同步执行；只允许把纯 UI 的显隐放到 `GetLocalPlayer()` 分支。
6. 模块初始化优先用 0 秒 Timer 启动，避免塞进臃肿的 `main` 导致后半段初始化未完成。
7. 不要在已经注入过同一模块的成品图上再次运行 `--script`，会出现函数/全局变量重复定义。
8. YDWE 脚本可能包含多个 `endglobals` 文本；必须插入到真正的主 globals 结束位置。
9. 在 1.27 上修改脚本后必须运行 pjass；不要只看 Python/文本替换是否成功。
10. 修改脚本换行符前先确认锚点文本本身的换行；混合 CRLF/LF 会让替换“找不到字符串”。

## 六、物品浏览器

物品浏览器通常把物品表硬编码在 `war3map.j` 中，修改物品后必须同步：

1. 新增 `ib_itemList[index]`。
2. 新增显示名 `ib_itemName[index]`。
3. 新增 GBK 匹配名 `ib_itemNameGbk[index]`。
4. 设置 `ib_itemCustom[index] = 1`。
5. 增加最终 `ib_itemCount`。
6. 给自定义物品技能加入 `IB_IsItemAbility` 保护。
7. 为 1.27 添加英文别名，例如：

```text
additem frostmourne
additem frost
additem I105
```

如果两个系统都监听 `additem`，同一命令可能添加两件物品并弹出两条消息。只保留一个入口。

## 七、模型、贴图和特效

### 7.1 MDX 不是完整资源

导入 MDX 时必须扫描其内部字符串，找出依赖的 BLP。实际案例：

```text
war3campImported\Frostmourne.mdx
  -> Frostmourne10.blp
  -> Frostmourne100.blp
```

只导入 MDX 时可能出现：

- 物品完全不可见。
- 只有地面光环，没有剑身。
- 看不到点击区域，因此无法拾取。

### 7.2 资源路径必须逐字一致

物品 `ifil`、技能 `acat`、脚本 `AddSpecialEffect` 的路径要与 MPQ 内部文件名一致，包括：

- 目录层级
- 大小写
- 反斜杠
- 文件扩展名

### 7.3 地面物品特效

- 每件物品只创建一个光环 effect。
- 用物品句柄做 key，防止定时器重复创建。
- 拾取后立即 `DestroyEffect` 并清理 hashtable。
- 物品移动超过阈值时再重建 effect，避免每帧闪动。
- 地面模型和光环是两套资源，不能互相替代。

### 7.4 图标绿色方块

检查：

- 正常图标 BLP 是否存在。
- `DIS...` 禁用图标是否存在于对应 disabled 目录。
- 菜单暂停时游戏会切换到禁用图标，所以只在正常状态下测试不够。
- 自制 BLP 的尺寸/调色板/编码必须正确。

## 八、MPQ、战役与容器

1. 原生注入必须保留原 MPQ 中所有旧条目，尤其没有 `(listfile)` 的地图。
2. `.w3n` 章节地图通常必须作为 store/no-compress 条目回写。
3. 战役共享对象数据与章节对象数据是两层；先查战役级，再查章节级。
4. 战役对象数据的 original 段可能使用带基对象前缀的字段 ID；通用四字字段解析器可能无法直接读取。优先使用本项目已验证的提取工具。
5. 合并对象数据时保留 orig/custom 分段，不能全部拍平成 custom。
6. 覆盖游戏目录成品前保留已知可运行副本。

## 九、运行时与系统环境

1. 1.27 游戏内通常不能直接输入中文，测试命令要用 ID 或英文别名。
2. 新模型/新对象/新说明需要退出当前地图重新进入；重新开始当前局未必重新读取地图资源。
3. 任务 NPC 嘴动但没有字幕，先检查客户端字幕开关。
4. 全屏卡死但声音继续，可能是 GPU/驱动/TDR，不要先归因于地图触发器。
5. `TdrDelay/TdrDdiDelay` 被放大只能用于排查，不应长期掩盖显卡驱动问题。

## 十、每次交付前的固定检查

- [ ] 确认目标地图和修改范围正确。
- [ ] 扫描所有自定义对象 ID，避免冲突。
- [ ] 物品 `iabi` 不超过 4 条，主动技能排第一。
- [ ] 物品模型、图标、技能特效所需 MDX/BLP 全部存在。
- [ ] JASS 通过 pjass，无新增错误。
- [ ] 地图通过 1.27 的 Devos Map Doctor 检查。
- [ ] 断言最终对象字段值：冷却、耗魔、目标类型、`idro/ipaw`、模型路径。
- [ ] 确认地图内脚本只有一份模块入口，没有重复函数。
- [ ] 对最终工作图和部署图计算 SHA-256 并一致。
- [ ] 记录测试命令，例如 `additem frostmourne`。
