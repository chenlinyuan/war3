# ALAS 离线改图工具

## 开发与验证约束

代理不得主动启动、截图、点击、输入或操作 Warcraft III、World Editor
或其他游戏/编辑器 GUI 进程，也不得使用 `-loadfile` 做代理自行实机测试。
静态检查、构建、pjass、归档校验、哈希和 Map Doctor 照常执行；需要实机
验证时，应给出准确测试步骤和预期现象，由用户运行并反馈结果。

当前版本：`v74`（2026-11-04）

`v74` 修复部分 Reforged 单图被神器说明与建筑冻结脚本审计误拦截：

- 审计器会依次读取顶层 `war3map.j`、`scripts\war3map.j` 和
  `Scripts\war3map.j`，不再把 `Scripts` 目录中的脚本误判为空；
- “不得拦截 issued order”的检查只针对霜之哀伤 `FR_*` 函数，不再误伤
  原地图自己的坚守位置、嗜血、武器切换等触发器；
- 修复后 Sunken City v1.8.5 等把脚本保存在 `Scripts\war3map.j` 且已有
  issued-order 逻辑的地图可以正常通过成品审计。

`v73` 增加默认开启的自动存档修复：

- 战役构建并通过成品审计后，按成品文件名或游戏内战役标题自动查找
  `Documents\Warcraft III\BattleNet\<档案>\Campaigns\Custom\<战役名>`；
- 使用刚生成的成品战役重新绑定所有 `.w3z` 及其伴随快照的地图校验和与
  SHA-1，先完整试修复和校验，再备份并写入；
- 已是最新的存档保留 `CURRENT` 状态并按成功处理；没有找到同名存档目录
  时只记录为跳过，不影响成品生成；
- GUI 勾选“自动修复存档（默认）”；CLI 默认开启，可用
  `--no-repair-saves` 关闭，或用 `--saves` 指定存档目录；
- 存档修复失败不会删除已经通过审计的成品，完成提示和构建报告会列出错误。

`v72` 修复“画面模式跟随游戏设置”只改了 `SupportedModes`、但战役英雄仍
被 skin 对象数据锁成经典模型的问题：

- 普通单位模型、英雄图标、投射物、属性、技能与装备数据全部保留；
- 构建结束时再次审计成品，任何英雄本体或头像模型锁残留都会报错。

- Lua 单图目前会明确拒绝，不会输出半成品。

`v68` 调整三神器按钮位、技能归属选择与 QT 开全图：

`v67` 修复 `additem <名称> <数量>` 可能无限创建物品：

- 原逻辑以“成功放进背包的数量”作为循环结束条件；满包、不可入包物品
  或拾取即消耗的物品会让该计数永远不增加，导致持续 `CreateItem`。
- 现改为每尝试创建一次就增加 `created`，最多执行用户请求的数量。
- 构建器和单图发布审计都会拒绝仍包含
  `exitwhen added >= count` 的脚本。

`v66` 完善无装备栏地图的技能归属：

- `auto` 在 Reforged 装备数据章节使用物品装备栏归属；其他章节以及 JASS
  单图/战役使用普通背包 + 英雄命令栏归属。
- `command` 不再只把两个归属开关写成 `false`，而是在 JASS 构建时生成
  专用脚本副本，移除编译期仍会解析的
  `BlzUnitItemInEquipmentSlot` / `ConvertLoadoutSlot` 分支。
- 无装备栏模式固定为：`I103.iabi=A101,A102,W091`、
  `I105.iabi=A106,A108,A109`、`I106.iabi=A110,A111,Aclq`；
  `A100/A105/A113` 由拾取/丢弃事件添加或移除；Lua 章节另在载入和入场
  时补同步，JASS 地图/战役在初始化时扫描已有英雄。
- 三件主动技能仍统一放在英雄命令栏坐标 `3,2`。蛋刀不再引用外层
  魔法书 `A116`；`command` 模式下 `iabi` 不含主动技能，`item` 模式下
  由 `A113` 直接承担，避免额外魔法书按钮。

运行时边界：`command` 仍然依赖 Reforged 3.0 的 `Blz*` API。低于
Reforged 的老地图即使没有 30 格背包也不能作为目标；其旧 `common.j`
本身不认识这些 API，构建会在 pjass 阶段拒绝写入。JASS 管线目前走
`command` 或 `item` 方案；其中 `item` 要求目标地图本身支持 Reforged
装备栏/新背包。

## 使用

双击发行目录中的 `ALAS-Offline.exe`：

1. 选择未注入 ALAS 的 `.w3n` 战役或 `.w3x/.w3m` 地图。
2. 工具自动识别脚本类型和已有 ALAS 模块。
3. 成品扩展名跟随源文件；战役默认保存到
   `Documents\Warcraft III\Campaigns`。
4. 点击“开始构建”。工具完成注入、目录审计、结构审计、规则审计和
   可选 Map Doctor 检查。

“自动修复存档”默认开启。构建成功后会查找与成品同名的存档目录，以便把
旧存档绑定到本次生成的地图身份。修复前工具会创建
`save-repair-backup-时间` 备份；找不到同名存档目录时会跳过，不会阻止
成品生成。

### 无损压缩

“无损压缩”默认开启，替代原来的“紧凑归档”选项：

- 战役：逐章重新压缩 MPQ 扇区、去重章内完全相同数据、清除未引用空洞；
- 单图：重新压缩并去重地图内部数据；
- 图片不做 BLP 重编码，所有内部文件在战役缩容前后逐字节校验；
- 章节仍以游戏要求的未压缩条目存放在外层战役中。

关闭后会保留旧数据布局以确保最大兼容性，代价是文件明显更大。
如果缩容器无法证明章节逐文件内容不变，工具会保留已通过注入读回校验的
未缩容成品并继续审计；地图仍可使用，代价是文件更大，不会因此中止整个战役。

### 被遗忘的王国专用处理

工具通过完整章节列表自动识别《被遗忘的王国》Lua 战役，并额外执行：

1. 修复 `war3map.wct` 中多算 1 字节的文本长度；
2. 修复鼠巢、坑道、巢母、黑暗犬和女妖任务逻辑；
3. 在 ALAS 构建后执行战役级无损压缩；
4. 审计 WCT/WTG 配对和任务修复标记。

该流程只对识别出的被遗忘的王国战役生效；其他地图仍可使用通用无损压缩。

### FT 游戏数据

“游戏数据改为 FT”默认关闭。开启后只对具有独立
`game_data_version` 字段的新版地图选择 TFT 数据；不会改动
`GameDataSet` 的对象数据布局，也不会切换 Reforged 画面。旧版 RoC/TFT
地图本来就由地图版本决定数据体系，会保持原样并记录跳过。

### 画面模式跟随游戏设置

“画面模式跟随游戏设置”默认关闭。开启后会把新版地图的
`supported_modes` 设为 `SD | HD`，允许经典和 Reforged 两套画面，
实际使用哪一套由游戏设置决定。旧版地图没有该字段，本来就不限制画面
模式，因此会保持原样。

旧版自定义战役常把标准英雄模型写进 skin 对象数据。此时只改
`supported_modes` 不会生效，因为 `war3campaignSkin.w3u` /
`war3mapSkin.w3u` 仍会指定经典模型。本选项会同时移除这些标准英雄的
`umdl`（本体）与 `upor`（头像）覆盖，让游戏在 SD 下使用经典模型、在 HD
下使用 Reforged 模型。普通单位与自定义装饰模型不会被清掉。

所有完整 ALAS 成品都会自动应用统一装备规则，包括装备不可出售、群体传送
使用澄海 3C 的 `AImt` 配置、埃辛诺斯战刃冲锋快捷键为 `C`。

## 离线边界

- 不访问网络、不上传地图、不调用在线 AI。
- 首次移植仍需要用户自己的干净源战役或地图。
- 自动存档修复要求 `node` 位于 `PATH` 中；缺少 Node.js 时会保留成品，
  并在完成提示中报告存档修复失败。
- 当前 ALAS 运行时依赖 Reforged 3.0。
- 游戏图标与完整物品/技能目录都有本地快照；没有安装游戏时仍可构建，
  但实际游玩仍需要用户自己的 Warcraft III。
- 不随工具分发用户战役、地图或暴雪地图内容。
- 加密、壳化而无法读取脚本的地图会在预检查或构建阶段停止。
