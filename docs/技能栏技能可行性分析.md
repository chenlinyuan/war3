# 技能栏手动释放 vs 聊天命令（可行性分析）

本文分析"把自定义技能加入英雄技能栏、由玩家手动点击释放"的可行性，
对比当前"聊天命令"实现的差异。

## 当前实现（聊天命令）

`deathfinger` / `criton` / `addskill` 等通过**聊天命令**触发：

- 优点：无需修改地图对象数据，通用任意地图，实现简单
- 缺点：不是"技能"，不在技能栏，不能像正常技能那样点击/设快捷键

## 目标（技能栏手动释放）

把技能做成**英雄技能栏里的一个图标**，玩家点击（或按快捷键）释放。

## 技术路径对比

### 方案 A：使用地图对象数据（war3map.w3a）创建自定义技能

**做法**：在 `war3map.w3a` 里新增一个自定义技能（基于某个标准技能改），
用 `UnitAddAbility` 加到英雄上，玩家即可在技能栏看到并点击。

| 步骤 | 说明 |
| --- | --- |
| 1 | 解析/生成 `war3map.w3a`（对象数据表） |
| 2 | 新增自定义技能条目（继承标准技能，改数值/名称/图标） |
| 3 | 用 HKE「添加/替换文件」把 w3a 写回地图 MPQ |
| 4 | 脚本里 `UnitAddAbility(hero, 'A000')` |

**难点**：

1. **w3a 格式复杂**：v2 格式含 per-level 数组、levelPointer 等，逐字节解析易错
   （本项目之前尝试解析时在 `AHad` 条目处漂移）。
2. **官方地图无 w3a**：Lost Temple 是 2006 官方图，**没有** `war3map.w3a`，
   需要**从零构造**一个（含文件头 + 表结构）。
3. **技能行为**：标准技能无法直接表达"秒杀任意单位含魔免"——
   - `ANfd`（死亡之指，亡灵）是**对非英雄单位造成伤害**，对英雄无效，且受魔免影响
   - 要实现"秒杀含魔免"，仍需**脚本配合**（技能只作触发器，实际由 JASS 结算）

**结论**：可行，但工作量大、风险高。**推荐组合**：用 w3a 加一个"占位技能"（图标/名称），
真正的效果仍由 JASS 事件结算（`EVENT_PLAYER_UNIT_SPELL_EFFECT` 检测技能施放）。

### 方案 B：直接给英雄加标准技能

**做法**：`UnitAddAbility(hero, 'AOcr')` 之类，加到技能栏。

- ✅ 简单，`addskill` 命令**已经做到**（技能会出现在技能栏）
- ❌ 只能加**地图已有的**技能，无法自定义"秒杀"这种效果
- ❌ 英雄技能需要 `SelectHeroSkill` + 技能点，普通单位技能则直接可用

**结论**：`addskill` 已经能把标准技能加到技能栏。若"死亡之指"用标准技能实现，
可以直接 `addskill`（但标准技能没有"秒杀含魔免"效果）。

### 方案 C：伪技能（技能栏图标 + JASS 事件）

**做法**：加一个**无害的占位技能**（如某个被动/无效果技能）到技能栏，
用 `EVENT_PLAYER_UNIT_SPELL_EFFECT` 检测玩家施放该技能，执行秒杀逻辑。

| 步骤 | 说明 |
| --- | --- |
| 1 | 加占位技能到英雄（可用标准技能或 w3a 自定义） |
| 2 | 注册 `EVENT_PLAYER_UNIT_SPELL_EFFECT` |
| 3 | 检测 `GetSpellAbilityId() == 占位技能` → 执行秒杀 |

**难点**：占位技能需要是"可点击施放"的主动技能，且施放后不产生副作用。
标准技能里没有完美的"空主动技能"，通常用 `ANcl`（连锁闪电）之类改数值为 0，
或自定义一个。

## 关于"死亡之指"的特殊性

用户要的"**秒杀任意怪物 + 对魔免生效**"，**标准 War3 技能无法直接实现**：

| 标准技能 | 效果 | 问题 |
| --- | --- | --- |
| `ANfd` 死亡之指 | 对非英雄单位造成伤害 | 对英雄无效，受魔免影响 |
| `AUdc` 死亡缠绕 | 伤害/治疗 | 受魔免影响 |
| `Ahrl` 妖术 | 变羊 | 对魔免无效 |

因此**无论如何都需要 JASS 脚本**来执行"UNIVERSAL 伤害秒杀"。
技能栏图标只是"触发器"，真正的秒杀逻辑在脚本里。

## 推荐实施路径

**分两步走**：

1. **第一步（已完成）**：聊天命令 `deathfinger` 实现秒杀逻辑 ✅
2. **第二步（可选）**：给地图加一个自定义主动技能（w3a），
   用 `EVENT_PLAYER_UNIT_SPELL_EFFECT` 检测施放后调用 `IB_FingerKillUnit`

第二步的脚本部分很简单（已有 `IB_FingerKillUnit`），
**主要工作量在 w3a 对象数据的生成与注入**。

## w3a 生成的技术要点（若要做）

- **格式**：`version(int=2)` + `originalCount(int)` + 条目... + `customCount(int)` + 条目...
- **条目**：`oldId(4) + newId(4) + 修改数(int)` + 每个修改 `modId(4) + 类型(int) + 值`
- **Lost Temple 无 w3a** → 需构造最小 w3a（customCount=1，一个自定义技能）
- **注入**：用 HKE「添加/替换文件」写回 `war3map.w3a`
- **风险**：格式错误会导致地图无法加载，需充分测试

## 结论

| 方案 | 技能栏图标 | 秒杀含魔免 | 工作量 | 风险 |
| --- | --- | --- | --- | --- |
| 当前（聊天命令） | ❌ | ✅ | 已完成 | 低 |
| A：w3a 自定义技能 + JASS | ✅ | ✅ | 高 | 中高 |
| B：标准技能 | ✅ | ❌ | 低 | 低 |
| C：伪技能 + JASS | ✅ | ✅ | 中 | 中 |

**建议**：若需要技能栏图标，采用**方案 C**（占位主动技能 + JASS 事件），
比方案 A 更简单可控。核心秒杀逻辑（`IB_FingerKillUnit`）已具备，只需补一个
可施放的占位技能。
