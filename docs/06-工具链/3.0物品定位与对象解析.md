# 3.0 物品定位与对象解析

适用于 Reforged 2.0 与 3.0 的内建物品、装备及物品技能查询。当前已验证版本：

| 版本 | 本机 CASC 根目录 |
| --- | --- |
| `2.0.4.23745` | `H:\Games\Warcraft III Reforged` |
| `3.0.1.24371` | `H:\Games\Warcraft III` |

“3.0 新增物品”不能只从项目里的离线目录、地图 `war3map.w3t` 或旧版
`ItemData.slk` 判断。它们可能过期，也可能只包含地图自定义对象。准确来源是当前
游戏安装目录的 CASC 原生数据。

整个过程是静态读取，不启动游戏或编辑器。

## 一键查询

```powershell
$env:WC3_GAME = "H:\Games\Warcraft III"

python tools\war3map-injector\lookup_wc3_item.py 贪婪之赐
python tools\war3map-injector\lookup_wc3_item.py ergg
python tools\war3map-injector\lookup_wc3_item.py "Gift of Greed"
python tools\war3map-injector\lookup_wc3_item.py ergg --json
```

脚本输出：

- `.build.info` 中的游戏版本；
- 物品的全部基础字段；
- 中文 `Name`、`Tip`、`Description`、`Ubertip`；
- `abilList` 引用的每条技能；
- 技能的 rawcode、基础对象、Targets Allowed、等级和数据字段。

`--game` 可覆盖 `WC3_GAME`：

```powershell
python tools\war3map-injector\lookup_wc3_item.py 贪婪之赐 `
  --game "H:\Games\Warcraft III"
```

## 底层检索顺序

1. 确认根目录同时有 `.build.info` 和 `Data\data`，并从 `.build.info`
   记录准确版本。
2. 用 `GameBase(locale="zhcn", balance=None)` 读取完整基础表。
   `balance=None` 很关键；某个 balance 子表可能缺少新增物品或技能。
3. 在 `Units\ItemData.slk` 中按四字符 ID、英文 `comment`、`scriptname`
   查找物品；再合并语言 CASC 中的 `ItemStrings.txt` 取得中文名和说明。
4. 读取物品 `abilList`，不要根据物品名称猜测效果。逐个到
   `Units\AbilityData.slk` 查 rawcode、基础对象、等级、目标和
   `DataA/DataB/...` 字段。
5. 字段含义不清楚时，继续查 `AbilityMetaData.slk`；编辑器显示名在
   `UI\WorldEditStrings.txt` 的 `WESTRING_AEVAL_*` 项。
6. 与上一个游戏版本的同名 ID 比较。2.0 不存在、3.0 存在，才能证明该
   rawcode 是版本新增；同名不同字段则表示改版。

## 已验证实例：贪婪之赐

3.0 CASC 中的物品记录：

| 字段 | 值 |
| --- | --- |
| ID | `ergg` |
| 中文名 | 贪婪之赐 |
| 英文注释 | `Gift of Greed` |
| 脚本名 | `GiftofGreed` |
| 分类 | `Equipment` |
| 等级/装备位 | 4 / `Ring` |
| 技能列表 | `AItj,AIsq,Aggp` |
| 标签 | `Boss Drop` |

关联技能：

| ID | 基础技能 | 实际数据 |
| --- | --- | --- |
| `AItj` | `AIat` | `DataA1=5`，攻击力 +5 |
| `AIsq` | `AIas` | `DataA1=0.05`，攻击速度 +5% |
| `Aggp` | `Asal` | `targs1=enemy,ground,nonhero`，`DataA1=0.5`，`DataB1=1` |

`2.0.4.23745` 中没有 `ergg`，也没有 `AIsq`、`Aggp`；因此这三条是
3.0 新增对象。`AItj` 与基础掠夺 `Asal` 在 2.0 已存在。

## 掠夺字段含义

`Asal` 的数据字段：

- `DataA`：Pillage Rate / 掠夺比率。`0.5` 表示 50%。
- `DataB`：Accumulation Step / 积累步长。`1` 表示按 1 点有效伤害平滑结算。

它不是“每点伤害固定兑换 0.5 金币”。底层按目标资源造价和掉血比例结算，
近似为：

```text
本次资源收益
≈ 目标资源造价 × 本次有效伤害 ÷ 目标最大生命 × 掠夺比率
```

只计算基础攻击的主要目标，通常受护甲减伤后的实际伤害影响。原生掠夺可读取
目标金币和木材造价；3.0 的“贪婪之赐”说明只承诺金币。具体碰撞、溅射、
召唤物和英雄边界仍需在目标版本做游戏内验证。

## 对象字段陷阱

- `comment` 是英文对象注释，不等于中文显示名。
- 中文名可能带 `|cAARRGGBB...|r` 颜色码，搜索前应去除。
- `tag="Boss Drop"` 只说明对象标签，不能证明某张地图实际放置或掉落它。
- `InBeta=1` 是数据表标记，不能据此认定该物品仍处于测试阶段。
- 物品 `iabi`/`abilList` 只有前四个有效技能；主动技能应放在前面。
- 在自定义地图里复制 `Asal` 时应使用新的技能 ID，避免与原生物品或其他
  `Aggp` 使用处共享后续改值。

## 阿克蒙德之手的替换判断

当前 `I103.iabi=A101,A102,W091`，占用 3 个被动槽，技术上还能加入 1 条
`Asal` 掠夺。因此“把脚本击杀掠夺改为原生贪婪掠夺”可以实现。

但它不是等价替换：

| 项目 | 当前脚本掠夺 | 贪婪之赐 `Asal` |
| --- | --- | --- |
| 触发 | 击杀后 | 基础攻击造成伤害时 |
| 英雄 | 有独立、更高公式 | `nonhero` 排除英雄 |
| 数值 | 等级公式 + 随机数 | 目标造价与伤害比例 |
| 反馈 | 自定义绿色“掠夺+N” | 原生物品被动，通常无自定义飘字 |
| 经济节奏 | 受击杀数限制 | 每次有效攻击持续滚资源 |

若替换，应关闭 `WG_PLUNDER_ENABLE`，避免脚本与原生被动双份结算，并同步
修改物品描述、配置和所有战役版本。更稳妥的做法是保留两种模式，在选定地图
单独启用 `pillage` 模式，先验证英雄、建筑、召唤物、溅射和高造价单位收益。
