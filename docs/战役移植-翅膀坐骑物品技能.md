# 把「翅膀/坐骑 + 物品/技能系统」移植到任意战役

> 2026-10-11 实战：`Campaigns\dz\182492.w3n`（战马，11 章）与 `182347.w3n`（27 章）。

## alas 命名规范

后续所有修改后的战役文件名统一以 `alas` 开头；已经修改过的战役（血色使命、
娜迦之怒、凌寒之怒、燃烧之怒等）再次改动时，也生成新的 `alas... .w3n` 文件，
不再沿用旧的 `（翅膀版）` 等命名。原始战役文件不覆盖。

首个实验版本：

`H:\Games\War3\Campaigns\alas序章 兽族大逃亡（翅膀物品技能版）.w3n`

战役列表显示名用文件头 `HM3W` 修改，不要为了改名改
`war3campaign.wts`；某些原版战役会校验 WTS，改了就报
`The file data is corrupt. File: war3campaign.wts`。

## 一条龙命令（以 <slug> 命名工作目录，源战役是 $src）

```powershell
$env:PYTHONIOENCODING="utf-8"
$src = "H:\Games\War3\Campaigns\dz\182492.w3n"

python tools\war3map-injector\port_wings_campaign.py extract "$src" --work maps\port\182492
python tools\war3map-injector\port_wings_campaign.py config  --work maps\port\182492 --config wings_config_182492
$env:WINGS_CONFIG="wings_config_182492"
python tools\war3map-injector\pick_ids.py "$src" --campaign --write     # 换掉撞车的 ID（战役用 --campaign）
python tools\war3map-injector\port_wings_campaign.py objects --work maps\port\182492 --config wings_config_182492
python tools\war3map-injector\port_wings_campaign.py name    --work maps\port\182492
python tools\war3map-injector\port_wings_campaign.py ib      --work maps\port\182492 --config wings_config_182492
python tools\war3map-injector\port_wings_campaign.py chapters --work maps\port\182492 --config wings_config_182492
python tools\war3map-injector\port_wings_campaign.py pack "$src" --work maps\port\182492 --out "H:\Games\War3\Campaigns\XXX（翅膀版）.w3n"
```

## 三个必须记住的点

1. **章节地图必须原样存储（不压缩）**——游戏是把章节当"内嵌归档"打开的。
   `pack` 已自动对所有 `.w3x/.w3m` 用 `--store` 写；验证用 `sfmpq_subarchive.ps1`，
   **11/27 章全部 `open-as-archive: OK` 才算过关**。
2. **`ib` 子命令给该战役现生成物品/技能表**（273 个游戏标准物品 + 该战役自己的自定义
   物品/技能 + 我们注入的东西），写到 `<work>/item-browser/f.j`。
   仓库里 `scripts/item-browser` 那份是别的图的表，**不要**直接拿去注入。
3. **ID 撞车**：`pick_ids.py <战役> --campaign --write` 会扫 `war3campaign.w3a/.w3t/.w3u/.w3h`
   + slk/txt，把冲突的 ID（常见是阿克蒙德之手的 `I000` / `A000-A002`）换成空闲的，
   写回该战役自己的 `wings_config_<slug>.py`。

## 移植到 KK 平台图（`194213` 燃烧之怒，2026-10-15）

### 坐骑档位：`config --mounts`

| 档位 | 数值 | 召唤小龙 |
| --- | --- | --- |
| `none` | **不带坐骑系统**：配置里 `MOUNTS = []` → 坐骑单位/蛋/骑乘中物品/挂载技能一条都不生成 | —— |
| `original`（默认） | 伤害/攻击类型/护甲/阴影/目标表/种族 **全部继承原版**（`None`），凤凰强制 `hp_regen=2.0` | 关（`summon_count=0`） |
| `full` | 伤害 **350**、混乱攻击、肉甲、飞行阴影、全天回血 2.0、目标 `air`、种族 `orc`（=`wings_config_1_5.py` 那套） | **开**（`summon_count=2`） |

两档都保留我们的 `splash`（含 `enemy`）—— 原版龙类 `ua1p` 不含 enemy，会溅射到友军。

> **2026-10-15 玩家定调：以后移植默认"不带坐骑"**（"后续坐骑系统在我没说明的前提下都不需要添加"）。
> 实现方式（不改 JASS）：`--mounts none` 把配置里的 `MOUNTS` 换成空表，三个生成器都按
> `CFG.MOUNTS` 决定生成与否 —— `gen_wing`（挂载/蛋使用/取消骑乘技能）、
> `gen_wing_item`（蛋 + 骑乘中物品）、`gen_w3u`（坐骑单位）本来就按表循环。
> 脚本侧 `wg_eggCount = 0`，坐骑那几段代码**全部空转**（所有 `wg_egg*` 访问都在
> `wg_eggCount` 循环或 slot/idx 范围检查里；`WG_MountSync` 只在有人骑乘时才做事），
> 所以不用为了"没坐骑"去改 JASS。顺带修掉一个隐患：`gen_wing` 开头原本直接
> `CFG.mount_by_key("phoenix")` 取坐骑模型路径，`MOUNTS = []` 时会 KeyError →
> 改成查不到就返回空串（只在 `if CFG.MOUNTS:` 里用到）。

### `chapters` 现在一步做三件事

① 注入 `scripts/wings` + 本战役的 `item-browser`；② 把 `_wing_*.w3*` 合并进**该章自己**的
对象数据（章节没有的文件就用我们的新建）；③ 把 5 个翅膀模型写进该章。
每章注入后 `inject_native.py` 会跑 pjass 门禁（`rc=0`）并逐文件读回比对，失败即停。
`pack --chapters-only` 只写章节，战役级对象数据/模型/wts 一个都不碰。

### `pick_ids.py --chapters`

逐章注入时，**章节自己**用掉的 ID 也会撞车，所以加了 `--chapters`：连 `w3n` 里每个
`.w3x/.w3m` 的 `war3map.w3a/w3t/w3u/w3h/w3q/w3b/w3d` 一起扫。
`194213` 实测：4751 个已占用 ID，唯一冲突是 `BUFFS.akmond = BEar` —— 那是我们**故意**
覆盖的原生 buff（阿克蒙德光环的图标靠它显示），不是真冲突，保持原样。

> 已知限制：`war3map.w3d`（装饰物）和 `war3campaign.w3d` 解析会报 `bad type`，
> 这两个文件里的 ID 没算进"已占用"（这两个文件我们也不注入，影响可忽略）。

### ⚠ 商城解锁的第二轮：`YPD0K` 把"切换背包"技能隐藏了（2026-10-16 玩家报的 bug）

玩家："凌寒之怒主角的背包切换后无法切换回去，那个切背包的技能不见了。"

查下来**不是**我们注入的东西坏了，而是"商城全解锁"把一个**陷阱型**商城道具一起放开了：

```jass
function Trig_..._6Conditions takes nothing returns boolean
    return GetSpellAbilityId() == 'A63G' and DzAPI_Map_HasMallItem(Player(0), "0000H00006") == true
endfunction
function Trig_..._6Actions takes nothing returns nothing
    if DzAPI_Map_HasMallItem(Player(0), "YPD0K") == true then

        call SetPlayerAbilityAvailable(Player(0), 'A63G', false)   // 切换背包（B）

endfunction
```

`YPD0K` **全战役只有这一处用途**：玩家**按过一次**切换背包（`A63G`）之后，就把
`A63G`（切换背包（B））和 `A63F`（炼化合成（V），战役 wts STRING 722）一起从技能栏隐藏
——作者是给"买了平台双背包"的玩家准备的（让他们用平台那套）。所以现象就是：按一次 B →
图标没了 → 切不回去。

**背包切换的原理**（顺带记一下，方便以后排查；`A63G` 在主角/复爵/两只宠物身上各有一份）：

```jass
// Trig_01…（主角）：三段搬运 = 主角 ↔ B1 ↔ B2 轮转
for i = 1..6: UnitAddItemSwapped(主角.槽[i],   udg_B1)
for i = 1..6: UnitAddItemSwapped(udg_B2.槽[i], 主角)
for i = 1..6: UnitAddItemSwapped(udg_B1.槽[i], udg_B2)
```

`udg_B1..B7` = 地图里预置的 7 个"背包单位"（`e60O` 型，名字在 wts 里是"切换背包用"/
"马甲背包专用"）。**只要这些单位还在、技能没被隐藏，切换就正常**。

### 征战值 / 暗誉值能不能继承到下一关？——**能**

玩家问"这几个战役里有一个征战值或者暗御值等，它们能继承到下一关吗"。查了两边的脚本，
**它们其实是同一个变量 `udg_rongyuzhi`**（同一套 KKWE 战役模板），走的是"**磁盘游戏缓存**
（`.w3v`）"，而不是存档码、也不是平台服务器值：

| | 燃烧之怒（ransao） | 凌寒之怒（wu0NN） |
|---|---|---|
| 变量 | `udg_rongyuzhi`（消息写"征战值"） | `udg_rongyuzhi`（消息写"暗誉值"） |
| 关末写盘 | `InitGameCacheBJ("xinran01.w3v")` + `StoreInteger(..., "rong","yu", udg_rongyuzhi)` | `InitGameCacheBJ("wuwang0NN.w3v")` + 同样的 `rong/yu` |
| 下一关读回 | `ReloadGameCachesFromDisk()` + `set udg_rongyuzhi = GetStoredInteger(..., "rong","yu")` | 同 |
| 一起继承的还有 | 主角/宠物（`RestoreUnitLocFacingAngleBJ`）、金币 `h/j`、木材 `m/c`、难度 `nan/du` | 主角/复爵/两只宠物的敏捷、金币木材、难度、`L/S`、乌药王次数 |

所以"连打下关"时是**继承**的；中途退出游戏再读档继续一般也能继承，因为缓存是**每关都
`ReloadGameCachesFromDisk()` 从磁盘 .w3v 读回**的，不依赖内存。

两个必须一起说明的例外：

1. **进度标记我们故意不让它继承**。脚本里能看到我们的注释
   `// IB: never persist progress flag xxx`（燃烧的 `udg_pp`/`udg_gaoshi`/`udg_qianghua`/
   `udg_rransaocishu`…）—— 那些是"已通关/已强化"的标记，继承下来会让后面的章节直接
   跳过任务目标，所以写盘那句被换成了 `DoNothing()`。**货币（征战值/暗誉值）没有被动过。**
2. `DzAPI_Map_GetStoredInteger(Player(0),"jtpx")` 这种是**平台服务器值**，单机存根恒返回 0
   （燃烧的"燃烧次数"就属于这类，本来也不跨关）。

平台图（KKWE 保护）有三个额外限制，流程和上面不完全一样：
